# 个人记账 Agent 调研、流程与安全边界

## 目标定位

这个 agent 应该先做“私人财务助理”，不是“自动财务执行器”。最小可用版本优先服务这些高频场景：

1. 每天用一句话记账，例如“午饭 28，支付宝”。
2. 自动分类、补日期、补支付方式，并允许用户确认或修改。
3. 周/月汇总支出，展示分类占比、预算剩余、异常项。
4. 做保守规划，例如“本月还剩多少钱能花”“如果想存 5000，每天还能花多少”。
5. 导出 CSV/JSON，保证用户随时能拿回自己的数据。

## 现有产品/Agent 做法

- 传统个人财务软件：GnuCash、HomeBank、Moneydance、Quicken、YNAB、Monarch、PocketSmith 等，核心是账户、分类、预算、报表、导入银行流水。它们通常不是 agent，但工作流成熟，值得借鉴账本模型和导入/导出能力。
- 新一代 AI 财务产品：例如 Spendify 这类产品强调上传银行账单、自动分类、现金流分析、健康评分、订阅识别、预算生成和预测。优点是省手工，风险是需要交出完整银行流水。
- 企业/SMB 财务 agent：Ramp、Affiniti 等方向更偏企业费用管理、采购、合规、预算和 CFO agent。它们的关键经验是审批流和权限分级：AI 可以检查、建议、草拟，但涉及付款、报税、签署、资金移动时必须暂停并交给人确认。
- 通用开源 agent：OpenClaw/Hermes 这类更像跨应用自动化框架，可接消息平台和外部服务。适合未来接入微信/Telegram/邮箱，但个人财务数据敏感，不能一开始就给宽权限。
- 学术/基准方向：金融 agent 平台如 FinRobot 更偏金融分析；安全研究如 GAAP 强调对私密数据做信息流控制，避免 agent 或模型被 prompt injection 诱导泄露数据。

## 推荐 MVP 流程

### 1. 记账

输入：

```text
今天午饭 28 元 支付宝
昨晚打车 46.5
工资收入 15000
```

处理：

1. LLM agent 把自然语言解析为结构化 JSON。
2. 本地校验日期、金额、收支方向、分类、账户和备注。
3. 生成候选账单，建议先 dry-run 或确认后写入。
4. 写入本地 SQLite，并保留原始输入，方便追溯。

### 2. 汇总

按月计算：

- 总收入、总支出、净现金流。
- 分类支出。
- 预算剩余和超支分类。
- 大额支出和异常频率。

### 3. 规划

先用确定性规则，而不是让 LLM 直接算账：

- `可花金额 = 月收入 - 已支出 - 储蓄目标`
- `日均可花 = 可花金额 / 本月剩余天数`
- 如果某分类预算使用率超过时间进度 20%，提示收缩。
- 如果净现金流为负，只给风险提醒，不给投资建议。

### 4. LLM Agent 层

LLM 是 agent 的交互入口，但只能调用安全的本地工具，不直接改账本、不直接执行资金动作：

1. `record`: LLM 解析单条账单，输出结构化 JSON，本地校验后写入。
2. `chat`: LLM 把用户意图路由到 `record`、`summary` 或 `plan`。
3. 报告中的数字来自数据库查询结果，不让模型凭空计算。
4. 付款、转账、投资、贷款、报税等高风险请求只能转成规划/提醒，不能执行。
5. LLM 不可用时停止自然语言解析并明确报错，不使用静默规则降级写入财务数据。

## 数据模型

最小表：

- `transactions`: id、date、amount、direction、category、account、merchant、note、raw_text、created_at
- `budgets`: month、category、amount
- `audit_log`: action、payload、created_at

后续可加：

- `accounts`: 现金、银行卡、支付宝、微信、信用卡。
- `recurring_rules`: 房租、会员订阅、贷款、工资。
- `attachments`: 小票、账单截图，本地加密存储。

## 安全边界

### 必须禁止

1. 不保存银行、支付宝、微信、券商等账号密码。
2. 不自动登录银行，不自动转账，不自动还款，不自动购买理财/股票/基金/币。
3. 不把完整账本默认发送给外部模型。
4. 不把财务建议包装成确定收益或专业投资/税务/法律建议。
5. 不执行来自账单备注、商户名、网页、邮件里的指令。

### 默认策略

1. 本地优先：SQLite 文件在本机，默认不联网。
2. 最小披露：调用 LLM 时只发送当前用户输入和必要上下文，不发送全量账本。
3. 人在环路：新增、删除、批量导入、预算修改都要可回滚；资金移动类动作只生成草稿。
4. 审计日志：关键动作记录 payload，方便排查。
5. 可导出：支持 CSV/JSON，避免数据被工具锁死。

### 权限分级

- Level 0：纯本地手工记账和查询。
- Level 1：允许 LLM 解析单条输入，但本地确认后写入。
- Level 2：允许读取用户手动上传的 CSV/账单 PDF，只做导入草稿。
- Level 3：允许只读银行聚合 API，例如 Plaid/银联开放接口；不保存原始凭证。
- Level 4：涉及付款、转账、投资、报税、贷款申请，一律只生成待办和风险提示，不执行。

## 后续路线

1. 加确认式交互：解析后先展示候选账单，用户输入 yes/edit。
2. 加 CSV 导入/导出和去重。
3. 加 Web UI 或长期聊天入口。
4. 加本地加密，例如 SQLCipher 或操作系统密钥链。
5. 加只读账单导入，并实现 prompt injection 防护测试。
6. 加可配置分类规则和月度复盘报告。
